One root cause behind issues 1, 3 and 4:

the chat renders modules from a MODULES map baked into bundle.nshc at package time — a snapshot. Everything else (Library, pop-outs, View Code) reads the live filesystem. Any module created or rewritten after the last build shows "module missing" in chat while launching fine as a pop-out. The versioned-artifact model (issue 4) makes this sharper: versions live on disk, and the chat must render whatever version a card points at.

Root cause

shell.tsx resolves cards via import { MODULES } from "../generated/index" — a static import compiled into the packaged bundle. R6's file exists (server wrote it at runtime), but it isn't in that snapshot. This is not a path bug — it's build-time vs runtime module loading.

The fix — how chat loads live modules

  • Same trick as pop-outs: the server already compiles a module to bytecode on demand for pop-outs (nsh build → .nshc → host). The chat needs the equivalent: a runtime-loadable module registry instead of the baked MODULES import.
  • Honest caveat: the packaged runner is hardened (no eval), so the app can't interpret new TSX itself. Loading runtime modules inside the chat needs the host to load a server-compiled chunk — likely a small upstream nsh change (the Rust Host already supports chunk bundles; it just isn't exposed). I'll confirm the cleanest path before writing it.
  • With versioning (issue 4), as built: registry keys are R6@v3 in MODULES, and chunk ids ship flat as R6v3.js (nsh-js validates flat <stem>.js — no paths). The chat resolves a card's pinned version through __nsh_import("R6v3.js").
  • Until that lands, every artifact generated after packaging will hit this. Dev mode is unaffected (JIT reads the filesystem).

    The model

  • Artifact (R6, title Rate Pad) owns a version tree: v1 → v2 → v3 …, each with a parent pointer. Files live as generated/R6/v3.tsx; R6.tsx is whatever current points at.
  • Cards record their version: generated · R6.tsx · v2 — the v1 card keeps rendering v1, the v2 card renders v2. Transcript stays honest; no more "which Rate Pad is this".
  • Current pointer per artifact: latest by default. Library shows it (v2); the row's click and pop-out launch current, whatever it points at.
  • Revert = move the pointer back (v4), not rewrite. Iterating from a non-tip version branches — next section.

    Tool calls on the version model
    tool calls the model gets

    revise(name, prompt, base_v?) — new version on the artifact; base_v = the branch point (defaults to current)
    launch_app(name) — pop open current
    close_app(name) — close its pop-out
    set_version(name, v) — move current (revert/restore)
    promote_app / demote_app — Mini Apps ↔ desktop widget
    view_code(name, v?) — read a version's source
    delete_app(name) — remove the artifact (all versions)

    names resolve bot-scope first, then global — same ordering as the @ picker.

    How I'd build it

  • Version store: generated/R6/v1.tsx, v2.tsx… + a versions(name, v, parent_v, prompt, created_at) table and a current_v pointer per artifact. R6.tsx stays the "current" file on disk so every existing path (pop-out build, /module, imports) just works.
  • @ picker: composer watches for @, queries a new /artifacts?q=&thread= — bot-thread apps first, then global/widgets, then attachments; match on title/file/name only.
  • Mention → context: a picked mention becomes a module://R6 attachment (already shipped path) — the model sees the current source + a revise tool to write back.
  • revise: the tool copies base_v → new version file, the model edits it, normal nsh check gate applies, then current_v moves to the new version and the turn card records v3.
  • Depends on issue 1: in-chat live module loading — versioned modules make it more urgent, since the registry keys become R6/v3.
