decision

The BetterOffice tooling uses import.meta.resolve, which the checker doesn't support — it's been left red awaiting your call. Three ways to go green.

Now — just check
$ nsh check app server tools1 fail
✓ app/shell.tsx ✓ app/App.tsx ✓ server/* ✗ tools/office/wasm.ts:41 — import.meta.resolve is not supported
Option A — rewrite the resolve
$ nsh check app server toolsall pass
// was: import.meta.resolve("../wasm/office.wasm") // now: resolve via asset path passed from the host ✓ tools/office/wasm.ts ✓ everything green
Clean gate, real fix. wasm.ts resolves the .wasm via an explicit path the server hands it. Cost: touches BetterOffice plumbing — isolated worktree, needs a small careful patch.
$ nsh check app server toolspass + skip
✓ app/shell.tsx ✓ app/App.tsx ✓ server/* ⊘ tools/office/** — excluded from check scope
One-line justfile change. Office is provenance tooling anyway — it doesn't ship in the app bundle, so checking it buys little. Cost: real regressions in office code won't be caught by the gate.
$ nsh check app server tools1 fail (known)
✓ … ✗ tools/office/wasm.ts — still red, documented as known-fail
Zero work. Cost: a permanently red gate trains everyone (and me) to ignore the gate — the next real failure hides in the noise.
